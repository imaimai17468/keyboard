# 6. ファーム

無線なら ZMK、有線だけなら QMK がよく使われます。ここでは ZMK を例にします。

## 作り方

- キーボードを ZMK の**シールド**として作ります（`boards/shields/<名前>/` に overlay・keymap・Kconfig・`.zmk.yml`）。マイコンのボード名は、ZMK が用意しているもの（XIAO nRF52840 なら `seeeduino_xiao_ble`）を使います。
- overlay のマトリクスのピンとキーマップは、配列の mm 座標とマトリクスの割り当ての表から**スクリプトで生成**します。手で書くと、配列を直したときにずれます。
- 物理配列（ZMK の physical layout）も、同じ座標から生成します。
- ビルドは GitHub Actions（ZMK の `build-user-config.yml`）で回すと、手元にビルドの環境が無くても `.uf2` が出ます。設定を初期化するための `settings_reset` も一緒にビルドしておきます。
- 電源スイッチを付けないなら、ZMK の soft off（キーの長押しで切り、キーを押すと復帰）を設定します。
  - 復帰元にマトリクス全体（kscan）を指定すると、**どのキーを押しても起きます**（かばんの中で当たっても起きる）。
  - 特定の 1 キーだけで起こすには、そのキーの行のピンを `gpio-keys` にして `zmk,gpio-key-wakeup-trigger` の `trigger` にし、そのキーの列のピンだけを `extra-gpios` に入れて、それを `soft_off_wakers` の復帰元にします（col2row の場合。ZMK の公式ドキュメント「Adding Soft Off To A Keyboard」）。実例では esc だけで起きるようにし、実機で動いた。
  - 2 キーの同時押しで起こすには、基板に論理回路（AND ゲート）が要ります。長押しのときだけ起こすには、公式の機能には無く、拡張モジュールが要ります。
- 状態ランプ（接続や電池の状態）は、マイコンに載っている LED を使う拡張（zmk-rgbled-widget など）で表示できます。

## ピンの対応は、2 つ以上の出典で照らす

- overlay に書くピン（`&gpio1 7` のような nRF のピン番号）と、基板のフットプリントのパッドの名前（D17 など）の対応は、**メーカーの Arduino の定義・KiCad のライブラリ・公式の図**を照らし合わせて決め、出典を記録します。
- 出典どうしで食い違う所や、食い違いの報告がある所は書き出しておき、組み立ての段階で実機で確かめる手順に入れます（実例: XIAO nRF52840 Plus の D17 と書かれたパッドは、実機では P1.03 で、Arduino の定義の P1.07 ではなかった。公式の図の取り違えの報告どおりだった）。
- 確かめられない所は、できれば使わないピンにします。

## 試験用のファームで確かめる

組み立てのときに、ある列や行がまるごと反応しないときは、ピンの対応を疑います。その列のピンだけを別の候補に変えた**試験用のファーム**を、試験用のブランチでビルドして書き込みます。反応すれば対応の間違いと分かり、生成のスクリプト（ピンの対応の表）を直します。overlay を手で直して終わりにしません。

## 分割キーボード

この節は、元の実例では作っておらず、確かめていない指針です。

- 左右で別のシールド（`<名前>_left`・`<名前>_right`）にし、`Kconfig.defconfig` で分割を有効にして（`ZMK_SPLIT`）、central にする側で `ZMK_SPLIT_ROLE_CENTRAL` を有効にします。書き方は ZMK の公式ドキュメントの「New Keyboard Shield」の分割の節と、既存の分割キーボード（Corne など）のシールドで確かめます。
- `build.yaml` に左右の両方と `settings_reset` を入れます。
- 左右の組み合わせ（ペアリング）が残ったままだとつながらないことがあるので、つながらないときは両方に `settings_reset` を書いてから入れ直します。

## 関門

GitHub Actions などでビルドが通り、`.uf2` が出る。ピンの対応の出典と、食い違う所の一覧がある。
