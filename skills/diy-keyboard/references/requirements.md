# 1. 仕様を決める

何を作るかを、使う人と一緒に決めます。ここで決めたことが、部品・基板・ケース・ファームのすべてを縛ります。あとで変えると、その先の段階を全部やり直すことになるので、急がずに決めます。

## 決めること

一度に 1 つずつ、次の表の上から順に聞きます。上の項目ほど、下の項目の選び方を縛るからです。使う人がすでに言ったことは聞き直しません。

| 項目 | 決めること | 決めると何が変わるか |
|---|---|---|
| 形 | 一体型か分割か。分割なら左右のつなぎ方（無線、TRRS などの有線、受信用のドングルを使う形）、親指のキーの数 | マイコンと電池の数、ファームの構成 |
| 配列 | キーの数と並び。既存の配列（MacBook、60%、Corne など）に近いか。KLE（keyboard-layout-editor）の JSON があるか | マトリクスの大きさ、基板とケースの大きさ |
| スイッチ | ロープロファイル（Kailh Choc V1・V2、Gateron ロープロなど）か、通常の高さ（MX 互換）か。ホットスワップにするか | 基板の部品の形、キーキャップの軸、ケースの高さ、キーの間隔 |
| キーの間隔 | 19.05 mm（MX の間隔）か、18 × 17 mm（Choc の詰めた間隔）か | 基板の大きさ、キーキャップの大きさ |
| 長いキーの支え | スタビライザーを使うか、スイッチを複数並べて支えるか | 基板の部品配置、押した重さ |
| マイコン | 無線なら nRF52840 の載ったモジュール（XIAO nRF52840 など）。有線だけなら RP2040 など | ピンの数、ファーム、アンテナの扱い、充電の回路 |
| ファーム | ZMK（無線に向く）か QMK（有線に向く）か | 書き方、キーマップの作り方 |
| 電源 | 電池の容量と大きさ、電源スイッチを付けるか（付けないなら ZMK の soft off で切る） | ケースの厚さ、電池を入れる場所 |
| ケース | 素材（アルミの CNC、樹脂の 3D 造形、アクリルの積層など）と仕上げ | 値段、誤差の大きさ、加工の制約 |
| キーキャップ | 既製品か、自分で造形するか。刻印の有無 | 費用、試作の要否 |
| 予算 | だいたいの上限 | 素材と工場の選び方 |
| 使う人の作業 | 半田付けの経験、持っている工具（はんだごて、テスター、やすりなど） | 手で付ける部品の大きさ、組み立ての手順の細かさ |

## 進め方

- 使う人が既存の配列を挙げたら、その配列の公開データ（KLE の JSON、メーカーの VIA の定義など）を探して、キーの寸法の基準にします。見つけたら出典を記録します。
- 配列を決めたら、**キーの並びを画像にして見せます**。1u・1.5u などの幅と合計の幅（例: 15u = 285.8 mm）を添えます。
- 紙に 1:1 で印刷して手を置いてもらうと、分割の角度や親指の位置を決めやすくなります。
- 作れない形はその理由を言います（例: Choc のスイッチ本体は約 15 mm 角なので、半分の高さの矢印キーを縦に 2 つ並べられない）。
- 迷った点は「案」として並べ、比べて決めた理由を残します。

## 関門

次の段階に進む前に、上の表の項目がすべて決まり、`docs/spec.md` に「確定事項」として書かれていること。決めていない項目があるなら、「仮」と書き、いつ決めるかを添えます。
