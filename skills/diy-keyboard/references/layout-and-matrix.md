# 3. 配列とマトリクス

## 配列を元データにする

- 配列は KLE 形式の JSON などで持ち、スクリプトで**キーごとの mm 座標**（中心の位置、幅、高さ、回転、そのキーを支えるスイッチの位置）に変換したファイルを作ります。これを唯一の元データにします。
- 基板の部品配置、ファームの物理配列（ZMK の physical layout など）、ケースの外形、キーキャップの外形は、すべてこのファイルから生成します。手で数値を書き写しません。
- 変換したら、キーの並びを画像にして、使う人と見比べます。
- JIS の Enter のような L 字のキーは、長方形を組み合わせた形として持ちます。

## マトリクスを組む

- マイコンの使えるピンの数を数えます。電池の電圧の測定や NFC など、ほかの用途に使われているピンを除きます。NFC のピンを GPIO にするには、ファームでの設定が要ることがあります（ZMK なら `nfct-pins-as-gpios`）。
- 行×列がキーの数以上で、行＋列がピンの数以下になるように決めます。例: 81 キーなら 9×9（18 本）。
- **電気的な行列は、見た目の行・列と一致しなくてかまいません。** ピンが足りないときは、物理的な行の端のキーを別の電気的な行にまとめます。割り当てはスクリプトで決め、表として残します。
- ダイオードは 1 キーに 1 個。向き（col2row など）をファームと同じにします。
- 1 つのキーを複数のスイッチで支えるときは、スイッチを並列につなぎ、ダイオードは 1 キーに 1 個にします。押した重さはスイッチの数だけ足されます（20 g のスイッチ 3 個で約 60 g）。

## 分割キーボード

この節は、元の実例（macjis）では作っておらず、確かめていない指針です。

- 左右それぞれにマイコンと電池を載せ、左右それぞれでマトリクスがピンに収まるようにします。
- ZMK なら、片方を central、もう片方を peripheral にし、左右で別のシールドとしてビルドします。キーマップは central 側に入ります。
- 基板は、左右で別の基板にするか、1 種類の基板を裏返して使う（リバーシブル）かを決めます。リバーシブルにすると発注の種類は減りますが、部品を表と裏のどちらに付けるかの間違いが起きやすくなります。
- 左右のつなぎ方は 3 通りあります。無線（左右それぞれに電池が要る）、TRRS などの有線（ケーブルとコネクタが要る）、受信用のドングル（第 3 のマイコンを PC に挿し、左右はどちらも peripheral）。
- 有線でつなぐときは、使うファームとその版が有線の分割に対応しているかを、ファームの公式ドキュメントで確かめます（ZMK は無線の分割が中心で、有線の対応は版によって違う）。片方の電池や USB で両方を動かす作りにするなら、電源の線の回し方も確かめます。TRRS のケーブルは、電源を入れたまま抜き挿しすると端子がショートすることがあるので、組み立ての案内に「抜き挿しは電源を切ってから」を入れます。
- 無線なら、電池・電源の切り方・充電の口が左右に 1 つずつ要ります。ケースも左右で別になるので、[case.md](case.md) の「はまる所の一覧」は左右それぞれに作ります。
- 左右をケーブルでつなぐなら、コネクタの位置とケースの穴を、両方の半分で確かめます。

## 関門

キーごとの mm 座標のファイルと、行・列・ピンの割り当ての表がある。ピンの数に収まり、使えないピンを避けている。
