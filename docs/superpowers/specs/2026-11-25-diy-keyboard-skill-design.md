# 自作キーボードのスキル（diy-keyboard）の設計

## 意図
macjis（このリポジトリ）を作った経験を、ほかの人が Claude Code と話しながら、自分のキーボードを基板から作れる指針にする。配列は自由で、分割キーボードや別の部品にも使える。生成ツールを配るのではなく、AI がその人用の設計とスクリプトを新しく作るための考え方・手順・ルール・確かめ方を渡す。

## 目標
- 使う人の希望（配列、一体型か分割か、スイッチ、マイコン、無線か有線か、ケースの素材、予算）を AI が聞き出し、部品を選び、設計データを作り、発注と組み立てまで付き添える
- 今回の失敗（ピンの対応の入れ替わり、カバーの隙間、USB の穴の奥行き、半田不良）を、注文前と組み立て中の確認で防げる
- macjis を実例として参照できる

## 目標にしないこと
- 決まった部品・決まったスクリプトの配布（macjis のスクリプトは実例であって土台ではない）
- 発注や支払いの代行（注文ボタンと支払いは人が押す）

## 失敗とみなすこと
- 図面の上では合うのに、届いた物が組めない
- 確かめていない部品や対応を、確かめたこととして使う

## 方式（検討した案）
- **A. スキル 1 つに、進め方と段階ごとの確認をまとめ、詳しい指針を references に分ける**（採用）。段階をまたぐ確認（基板とケースの寸法の受け渡し）を 1 か所で扱える。
- B. 段階ごとに別のスキル。境目の確認が抜けやすく、今回の失敗は境目で起きたので採らない。
- C. 指針＋部品ごとの土台のコード。部品も AI が新しく選ぶという狙いから外れるので採らない。

## 置き場所と形
- `skills/diy-keyboard/`（このリポジトリは公開。`npx skills add imaimai17468/keyboard` で入れられる）
- `SKILL.md`: 使う場面、進め方の段階と各段階の関門、話し方、ルールの要点、references への案内
- `references/`: 仕様決め、部品選び、配列とマトリクス、基板、ケース、キーキャップ、ファーム、見積もりと発注、組み立てと動作確認、失敗の一覧
- 分割キーボードは macjis で作っていないため、確かめていない指針であることを明記する
- 書くのは日本語（使う人と同じ言葉で話す前提）。ほかの言葉の人とは、AI がその言葉に直して話す

## 作り手に任せること
- 各 reference の分量と章立て
- 部品の候補は例として挙げ、提案するときは必ず在庫と価格をその時点で確かめさせる
